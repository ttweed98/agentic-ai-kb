# Map Microsoft's free training onto Koch's agents

**Microsoft and GitHub offer enough free training to cover all eight layers of Koch's design, and the strongest and most current of it is in Python.** No single course matches the whole design: Claude in the loop, Teams in front, a builder agent and a QA agent with a rework loop, MCP tools, a human approval, and a boundary rule of "no ID, no owner, no approval, then stop". The pieces exist separately, and you have to put them together yourself. Five free resources do most of the work. The **Microsoft Teams SDK for Python**, which went GA on May 1, 2026, covers the Teams front end and the Approve/Reject Adaptive Card. **Microsoft Agent Framework 1.0** (April 2026) has an Anthropic client, ready-made multi-agent orchestrations and a built-in `approval_mode="always_require"` gate. The **Microsoft Entra Agent ID** docs and modules map closely onto the ID/owner/approval rule. **PyRIT** is Microsoft's open-source red-teaming tool and supports Anthropic targets directly. The free **GH-600 "Developing in Agentic AI Systems"** path covers the AI-assisted software-delivery side. Most of Microsoft's material assumes Azure or Foundry hosting. Koch runs on AWS, so what you can use directly is the code-level, vendor-neutral material: the SDKs, the orchestration and approval patterns, the identity model, OpenTelemetry and PyRIT. The managed Azure services mostly do not apply. On MCP specifically, almost nothing Microsoft publishes says which spec revision it targets. Only a small part of the `mcp-for-beginners` curriculum is explicitly aligned to 2026-07-28, so it should stay out of your MCPA study except for that part. The practical sequence: finish MCPA, use the free Ignite Digital sessions (Nov 17–20) for orientation, then work through four short tracks. All of the training content below is free to read. Hands-on labs often need a paid Azure subscription or a Copilot Studio license, and every certification exam named here is paid.

## The Teams front end: use the Python Teams SDK, which went GA in May 2026

Microsoft currently offers two code-first SDKs for a Teams front end, and both have Python packages. The **Microsoft 365 Agents SDK** replaces Bot Framework and serves several channels: Teams, Copilot, web and Slack. Microsoft describes it as making "no assumptions about what generates the response", which means a Claude backend is supported by design, although Microsoft never names Anthropic. It ships a Teams hosting package (`microsoft-agents-hosting-msteams`) and a Python `cards` sample ([Agents SDK overview](https://learn.microsoft.com/en-us/microsoft-365/agents-sdk/agents-sdk-overview); [Python reference](https://learn.microsoft.com/en-us/python/api/agent-sdk-python/agents-overview)). The **Microsoft Teams SDK** (formerly Teams AI Library v2) is Teams-only and simpler. **Its Python support reached general availability on May 1, 2026**: install with `pip install microsoft-teams-apps`, and it supports streaming replies and Adaptive Cards. Microsoft says it plugs into "your existing Python server, agent framework, or LLM stack" ([Microsoft 365 Dev Blog](https://devblogs.microsoft.com/microsoft365dev/python-support-for-the-microsoft-teams-sdk-is-now-generally-available/)). That supersedes the November 2025 announcement, which still called Python a preview ([Teams SDK announcement](https://devblogs.microsoft.com/microsoft365dev/announcing-the-updated-teams-ai-library-and-mcp-support/)). If Teams is the only front end Koch needs, the Teams SDK is the shorter path. If the same agent may later appear in Slack or on the web, choose the Agents SDK.

The human approval step in Teams is built from **Universal Actions for Adaptive Cards**. The agent posts a card with Approve and Reject buttons using `Action.Execute`. The bot's invoke handler records the decision. "Up-to-date views" then refresh the card so the approver and the requester each see the right state, and "Sequential Workflows" carries a multi-step flow ([Sequential Workflows](https://learn.microsoft.com/en-us/microsoftteams/platform/task-modules-and-cards/cards/Universal-actions-for-adaptive-cards/Sequential-Workflows); [Up-to-date views](https://learn.microsoft.com/en-us/microsoftteams/platform/task-modules-and-cards/cards/universal-actions-for-adaptive-cards/up-to-date-views)). Both URLs came from search and were not opened. **Microsoft publishes no single sample that combines an LLM backend with an Approve/Reject card.** You would build it from the Python cards sample and these docs.

For structured coursework, the free path **"Build Custom Engine Agents with the Microsoft 365 Agents SDK"** is the self-paced counterpart of the paid instructor-led MS-4015 course. It has three modules, and the last has nine units that run from project creation through deployment to Azure App Service and Teams ([learning path](https://learn.microsoft.com/en-us/training/paths/build-custom-copilots-microsoft-teams); [module 3](https://learn.microsoft.com/en-us/training/modules/build-your-custom-agent-teams/)). It has three weaknesses for you. Its model is Azure OpenAI, its lab language is not stated and is probably C# or TypeScript, and it was last updated in October 2025. The free 9-unit **"Choose a Custom AI Agent Development Path"** module is the best starting point for orientation. Unit 5, "Build custom engine agents for Microsoft Teams", is where Koch's pattern fits, because a custom engine agent brings its own model ([module](https://learn.microsoft.com/en-us/training/modules/choose-ai-agent-development-path/)). The **Microsoft 365 Agents Toolkit**, the renamed Teams Toolkit, is built for TypeScript/JavaScript and .NET, and its documentation shows no Python templates ([Agents Toolkit overview](https://learn.microsoft.com/en-us/microsoftteams/platform/toolkit/overview-agents-toolkit)). A Python developer might still use it only for app registration and sideloading, but nobody has verified that this works smoothly.

Copilot Studio is the low-code alternative. Makers can choose Claude as the orchestration model after an admin opts in, and the free 7-unit advanced module **"Integrate Agents with External Systems via MCP in Microsoft Copilot Studio"** covers connecting MCP servers with API-key or OAuth 2.0 authentication ([Copilot blog](https://www.microsoft.com/en-us/microsoft-copilot/blog/copilot-studio/anthropic-joins-the-multi-model-lineup-in-microsoft-copilot-studio/); [MCP module](https://learn.microsoft.com/en-us/training/modules/integrate-agents-external-systems-mcp-copilot-studio/)). Its **multistage approvals** combine human stages, AI stages and conditions, but they were still in **Preview** as of the June 30, 2026 docs, and AI stages consume Copilot Credits ([multistage approvals](https://learn.microsoft.com/en-us/microsoft-copilot-studio/flows-advanced-approvals)). **Agent Academy** is free and open-source, and its Operative rank includes "Human Oversight" and "Integrate with MCP Servers" missions. You must bring your own licensed environment, though, and the MCP mission requires joining the Frontier program ([Agent Academy](https://microsoft.github.io/agent-academy/)). Copilot Studio becomes relevant only if Koch decides to have Microsoft host the orchestration. For a Claude backend that Koch runs itself on AWS, Copilot Studio is the wrong place to spend time.

## Claude and orchestration: Agent Framework 1.0 has the builder/QA patterns and an approval gate

**Microsoft Agent Framework** replaces both Semantic Kernel and AutoGen. It reached **1.0 for Python and .NET on April 3, 2026**, with long-term support. It ships stable sequential, concurrent, handoff, group-chat and Magentic-One orchestrations, discovers tools from MCP servers, and treats **Anthropic Claude as a first-party connector** ([Agent Framework 1.0 devblog](https://devblogs.microsoft.com/agent-framework/microsoft-agent-framework-version-1-0/)). Its Anthropic provider exposes `AnthropicClient`, `AnthropicFoundryClient`, **`AnthropicBedrockClient`** and `AnthropicVertexClient`. That means an agent running on AWS against Bedrock is in scope, not just a pattern you would have to adapt. The package is still pre-release (`pip install agent-framework-anthropic --pre`) ([Anthropic provider](https://learn.microsoft.com/en-us/agent-framework/agents/providers/anthropic)). Koch's builder agent, QA agent and rework loop correspond to a sequential or group-chat orchestration in which the QA agent sends work back to the builder. The closest free hands-on practice is **lab 08, "Develop a multi-agent solution with Microsoft Agent Framework"**, and lab 07 introduces the SDK first ([lab 08](https://microsoftlearning.github.io/mslearn-ai-agents/Instructions/Exercises/08-agent-framework-multi-agents.html); [lab 07](https://microsoftlearning.github.io/mslearn-ai-agents/Instructions/Exercises/07-agent-framework.html)). Expect those labs to use Azure-hosted OpenAI models rather than Claude. The research could not confirm which model they use.

The framework's **human-in-the-loop support is the most directly reusable Microsoft code for Koch's approval rule**. Marking a tool with `@tool(approval_mode="always_require")` makes every call to it stop and emit a `function_approval_request`. Workflow-level pauses use `ctx.request_info(...)` with a `@response_handler`, and checkpoints save pending requests so an approval can arrive hours later. The docs recommend `always_require` for production and say tool approval "works with any function-tool call", including under the Anthropic client ([HITL doc](https://learn.microsoft.com/en-us/agent-framework/workflows/human-in-the-loop); [tool-approval sample](https://github.com/microsoft/agent-framework/blob/main/python/samples/03-workflows/tool-approval/sequential_builder_tool_approval.py)). Connecting that pending request to a Teams Adaptive Card is a reasonable design, but no Microsoft source documents it.

For Claude model access, Microsoft's own docs cover Claude only as hosted in **Microsoft Foundry**. Claude became generally available there in mid-2026 through the native Messages API at `https://<resource>.services.ai.azure.com/anthropic`, called with `from anthropic import AnthropicFoundry` and Entra ID authentication. The Foundry deployment also supports tool use and the **MCP connector**, which lets Claude call remote MCP servers directly from the Messages API ([Foundry June 2026 roundup](https://devblogs.microsoft.com/foundry/whats-new-in-microsoft-foundry-june-2026/); [how-to](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/how-to/use-foundry-models-claude); [concept page](https://learn.microsoft.com/en-us/azure/foundry/foundry-models/concepts/claude-models)). Since Koch runs on AWS, read these pages for the API shape and skip the Foundry setup. The only official Microsoft Learn walkthrough that pairs Claude with Teams is the **Agent 365 "quickstart-nodejs-claude"**. It scaffolds a Claude Agent SDK agent, adds Microsoft 365 tools over MCP, wires in Agent 365 identity and observability, and publishes to Teams and Outlook. **It is Node.js only**, but it is the clearest view of how Microsoft intends identity, MCP and telemetry to fit around a Claude agent ([quickstart](https://learn.microsoft.com/en-us/microsoft-agent-365/developer/quickstart-nodejs-claude)).

The free 18-lesson **microsoft/ai-agents-for-beginners** course is Python-notebook based and runs on Agent Framework. Lessons 08 (multi-agent), 10 (production), 14 (Agent Framework) and 18 (security) are relevant to the builder/QA design ([repo](https://github.com/microsoft/ai-agents-for-beginners)).

On MCP, keep to your rule of studying only 2026-07-28 material. The README of **mcp-for-beginners** says the curriculum teaches 2026-07-28, but it also admits that "some hands-on examples remain explicitly versioned to 2025-11-25". Its changelog shows that only **Module 08 and its July 29, 2026 companion lesson** are explicitly "aligned with the final 2026-07-28 spec". Lesson 1.1 ("What's Changed") was written against the release candidate on July 2, and nothing confirms it was revised after the final spec shipped ([README](https://raw.githubusercontent.com/microsoft/mcp-for-beginners/main/README.md); [changelog](https://raw.githubusercontent.com/microsoft/mcp-for-beginners/main/changelog.md)). The Microsoft Learn MCP pages for Foundry, Azure Functions and Copilot Studio, and Lesson 11 of ai-agents-for-beginners, do not state any spec revision. They teach how to connect a product, not how the protocol works. Use them for work integration after MCPA and never as exam sources.

## The boundary layer: Microsoft's most relevant material is on identity and guardrails

The boundary your team owns ("no ID, no owner, no approval, then stop") lines up more closely with Microsoft's training than any other layer. **Microsoft Entra Agent ID is generally available.** It gives each agent its own identity type, along with blueprints, **owners and sponsors**, access packages, Conditional Access policy templates for autonomous and on-behalf-of agents, and ID Protection for risky agents. It also explicitly supports **non-Microsoft agents, including AWS Bedrock** ([What's new in Agent ID](https://learn.microsoft.com/en-us/entra/agent-id/whats-new-agent-id)). The "manage owners and sponsors", "access packages for agents" and "configure third-party agents" pages are the ones most relevant to Koch's rule, and all three are linked from the [Entra Agent ID hub](https://learn.microsoft.com/en-us/entra/agent-id/). The free 8-unit module **"Introduction to Microsoft Entra Agent ID"** (updated 2026-04-21) covers how agent identities differ from service principals and managed identities ([module](https://learn.microsoft.com/en-us/training/modules/introduction-entra-agent-id/)). Since Teams sits in Koch's M365 tenant, Entra Agent ID is a realistic control even with Claude on AWS behind it. Licensing requirements were not found anywhere in the research.

The best guardrails path is **"Implement security for AI"**, nine free modules updated May 2026. It covers secure access for Entra Agent Identity, Defender XDR identity risk, Copilot Studio real-time protection, the Foundry AI Gateway, Foundry guardrails, Defender for AI Services, **Agent 365**, and Purview DSPM for AI ([path](https://learn.microsoft.com/en-us/training/paths/implement-ai-security/)). The advanced path **"Deploy and govern enterprise agentic AI solutions on Azure"** (AI-500) is closer to day-to-day engineering. It includes CI/CD for multi-agent systems in GitHub Actions with automated rollback when quality regresses, zero-trust per-agent identities, and a module on **approval workflows** and change management across the agent lifecycle ([path](https://learn.microsoft.com/en-us/training/paths/aaai-3-deploy-govern-agentic-ai-solutions-azure/)). **Prompt Shields** detects direct jailbreaks and indirect injection hidden in documents or tool output. Its standalone API accepts plain text, so a Python pre-check could call it before passing tool results to Claude. Calls are billed by consumption ([Prompt Shields](https://learn.microsoft.com/en-us/azure/ai-services/content-safety/concepts/jailbreak-detection)).

For evaluation, **Foundry Observability** documents agent evaluators for tool-call accuracy, task completion and task adherence. Its tracing is built on **OpenTelemetry**, which is vendor-neutral and which Agent Framework emits ([Foundry observability](https://learn.microsoft.com/en-us/azure/foundry/concepts/observability)). Take the concepts and the OTel approach. The managed services do not carry over. The **AI Red Teaming Agent explicitly does not support non-Foundry agents or function tool calls**, so it cannot test Koch's agent ([Red Teaming Agent](https://learn.microsoft.com/azure/ai-foundry/concepts/ai-red-teaming-agent)). What does carry over is **PyRIT**, Microsoft's open-source red-teaming framework (v1.1.0, `pip install pyrit`). It supports **Anthropic** targets and custom HTTP endpoints natively, so it can attack the whole agent endpoint rather than just the model, and it can run as a pre-go-live gate in CI ([PyRIT](https://microsoft.github.io/PyRIT/1.1.0/)). No official free PyRIT course was found, so the docs are the curriculum.

## The software-delivery side: GH-600 is the closest match

The new **GitHub Certified: Agentic AI Developer (Exam GH-600)** is the Microsoft credential closest to Koch's whole design. It measures six weighted domains: tool use and environment interaction (**20–25%**, the largest), multi-agent orchestration (15–20%), evaluation and error analysis (15–20%), architecture and SDLC (15–20%), memory and state (10–15%), and **guardrails and accountability** (10–15%). The exam runs 120 minutes, English only, through Pearson VUE, and is paid at a regional price ([GH-600 page](https://learn.microsoft.com/en-us/credentials/certifications/agentic-ai-developer/)). Its free prep is course **GH-600T00 "Developing in Agentic AI Systems"**, updated 2026-07-28. Part 1 is verified: "Foundations of Agentic AI in GitHub", "Designing Agent Architecture and SDLC Integration", and "Tooling, MCP, and Agent Execution Environments" ([Part 1 path](https://learn.microsoft.com/en-us/training/paths/gh-developing-agentic-systems-1/); [course](https://learn.microsoft.com/en-us/training/courses/gh-600t00)). According to training partners, Part 2 covers multi-agent orchestration, memory/state/evaluation, and governance ([Fast Lane](https://www.fastlanetraining.ca/course/microsoft-gh-600t00)), but **its URL is unverified** (the likely address is `.../paths/gh-developing-agentic-systems-2/`). These domains appear to line up with the themes of *Building the Software Factory*, which makes GH-600T00 a good companion to the book. That match is inferred from the domain list and has not been checked against the book's chapters.

Nine free **GitHub Skills** exercise repos cover the hands-on side. The most relevant are `expand-your-team-with-copilot` (the coding agent working from issues), `integrate-mcp-with-copilot`, `agent-orchestration-build-your-ai-dream-team`, `customize-your-github-copilot-experience`, and `agentic-workflows-that-read-the-room` ([github.com/skills](https://github.com/skills)). skills.github.com now redirects to GitHub Learn. Note the renames: GitHub's docs now call the coding agent the **Copilot cloud agent**. It works one branch per task, opens one PR, runs sessions capped at 59 minutes, and sets up its environment from `copilot-setup-steps.yml` ([cloud agent docs](https://docs.github.com/en/copilot/concepts/agents/coding-agent/about-coding-agent)). **GitHub Agentic Workflows** (`gh aw`) compile Markdown workflows into Actions `.lock.yml` files. It supports **Claude Code** as an engine, and its tutorial example is a PR reviewer that checks test coverage, which is essentially a QA-agent stage in CI. It is in **public preview** ([gh-aw tutorial](https://docs.github.com/en/actions/tutorials/develop-agentic-workflows-in-github-actions)). The GitHub MCP server's `request_copilot_review` tool is GitHub's built-in version of a builder-then-review gate ([github-mcp-server](https://github.com/github/github-mcp-server)). **Spec Kit** is current and free, with docs and a video overview. It now uses hyphenated commands such as `/speckit-specify` ([spec-kit](https://github.com/github/spec-kit)).

## Conclusion

Microsoft's agent training is built around Azure and Copilot, so at first glance it looks like a poor match for a Claude-on-AWS shop. In practice, Microsoft's investments have become vendor-neutral where it matters for Koch. Agent Framework has an Anthropic client with a Bedrock option. Entra Agent ID governs agents from other vendors. PyRIT attacks any HTTP endpoint. The Teams SDK accepts any LLM stack. **Learn the code-level patterns from Microsoft and skip its hosting services**, and nearly every hour carries over. Agent Framework's `approval_mode="always_require"` combined with Entra Agent ID's owner and sponsor model is close to a ready-made implementation of your team's boundary rule. That makes those two the best value of anything listed.

For MCPA, the useful result is mostly what to avoid. Microsoft's large MCP catalog is largely out of date or does not say which revision it targets, so the spec should stay your primary source and Microsoft material should come in only where it is explicitly dated to 2026-07-28. For your work learning, GH-600 is the one Microsoft credential that covers the whole loop: tools, multi-agent orchestration, evaluation and guardrails. If you want a credential after MCPA, it is the natural next one, though Ignite vouchers have historically excluded GitHub exams.
